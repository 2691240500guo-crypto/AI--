## 模块一：项目总体定位与需求理解（12 分）

**1. AI原生人才平台整体定位，与传统 HR 系统的差异（4 分）★/◎**
- 定位：面向政企的 **AI 原生数字化人才平台**——不是"人力资源管理系统 + AI 外挂"，而是把大模型能力作为**业务原语**嵌入人才全生命周期：档案、测评、匹配、培训、决策、问答。
- 与传统 HR（如 e-HR / ERP-HR 模块）差异：
  - 数据侧：传统 HR 存表单字段；本平台沉淀**结构化档案 + AI 研判报告 + 向量化语义库**三类资产；
  - 能力侧：传统 HR 靠人工筛选；本平台以 **RAG + Agent + NL2SQL + Skills** 提供可对话、可解释、可编排的智能服务；
  - 入口侧：管理端（HR/管理员）＋员工端小程序双端协同，而非单一 PC 后台。

**2. 服务对象、政企应用场景、建设核心价值（4 分）**
- 对象：三类角色——管理员（系统配置/权限）、HR/用人部门（招聘与人才运营）、员工（自助档案/测评/培训/问答）。
- 场景：简历入库即画像、岗位缺编即预警补位、按岗找人与按人找岗双向匹配、短板即培训、业务问题自然语言问数。
- 核心价值：**人岗匹配提效、人才盘点可量化、供需错配预警前置**。

**3. 原始需求要点、核心约束与建设底线（4 分）**
- 要点：简历→画像→测评→匹配→培训→报表→问答 的完整闭环；数据/接口/权限统一。
- 约束与底线（本项目 AGENTS 开发规范明确）：
  - 后端统一 FastAPI + SQLAlchemy 分层（router→service→dao→model），业务规则不入 router；
  - 模块间只走共享表/service 契约，不跨域改表；
  - 密钥、真实简历不入代码/种子；外部 AI 调用必须超时、失败降级（不允许挂死）；
  - 排序/判分口径后端权威，前端不做可信计算。

## 模块二：整体技术架构与技术栈落地（20 分）

**1. 六层架构（6 分）◎**

**2. 强制技术栈落地说明（8 分）——逐项讲"用途+实际落地形态"**

**4. 扩展性与部署能力（3 分）◎**

## 模块三：核心 AI 技术能力设计（28 分）——★本人深度负责其中 Agent 匹配链路

**1. RAG 检索增强生成（6 分）◎**
- 数据源：人才简历原文、AI 报告、知识文档 → 解析落库 + 切块向量化（Milvus）；
- 检索策略：混合召回（向量 TopK + 关键词）+ 重排，答案要求"不编造"（答不出返回档案未记录）；
- 权限隔离：按端/角色控制可问答范围；检索准确率通过测试集 P/R 指标度量（见 Q1）。

**2. AI Agent 多智能体体系（8 分）★（重点讲 Agent ②与匹配 Agent）**
- 五大 Agent 分工：档案解析 Agent（简历→画像/标签/报告）、测评研判 Agent（能力雷达/等级回写）、**岗位人才匹配 Agent（★ 岗位解析→双向匹配→预警，本人负责）**、培训规划 Agent（短板→课程/计划）、数据问数 Agent（NL2SQL）。
- LangGraph 工作流（以匹配为例，`app/ai/agents/match_agent.py` + `app/ai/graph.py`）：
  - **解析**：需求文本→LLM 结构化抽取（技能标准/学历/年限/综合素质），失败自动**规则兜底**（正则拆关键词，绝不让接口失败）→ `parsed_json` 落岗位；
  - **双向匹配**：岗位→人才（向量召回 TopK×3 → 硬过滤 → 软加权打分 → 0-100 综合分）与 人才→岗位 共用同一打分函数，方向反查；
  - **可解释**：四维得分（技能/学历/经验/素质）+ 雷达可视化 + LLM/规则生成自然语言解释，支持 force 重生成；
  - **状态与人工介入**：匹配结果落 `match_result`（幂等），状态机 候选(0)→推荐(1)→录用(2)，人工可介入改状态/保温，Agent 不覆盖已有结论；
  - **分支/循环**：预警链路在匹配成功后分支触发（空缺检测→TopN 补位→24h 去重→消息中心），循环体现在"跟进超期→保温提醒→重新加热"。

**3. Skills 可编排技能组件库（4 分）◎★**
- 组件封装：画像构建、向量化、解析、打分、预警为可复用函数/工具；
- 编排：Agent 通过 LangGraph 按需组合（解析→匹配→解释→预警为一条可编排链路）；触发机制支持显式调用与事件触发（匹配落库后自动检测空缺）；复用：岗位匹配与人才储备预警共用同一打分与解析组件。

**4. Vanna.ai NL2SQL（5 分）◎**
口语问数→安全转 SQL→结果图表/报告；数据权限联动：按角色限定可查表/字段，取数 SQL 生成后二次校验（防越权查询）。

**5. Dify AI 中台（5 分）◎**
模型管理（多底座切换）、Prompt 工程（模板集中维护）、知识库运维（上传/切分/更新）、日志监控（Agent 任务留痕、失败可查）。

## 模块四：AI 原生业务功能模块（18 分）——★重点：本人模块评分点

**1. AI 智能人才档案与数字画像（3 分）◎**：简历多格式解析（LLM 抽取+规则补全）→ 主档结构化 + AI 报告（技能/亮点/短板/潜力）→ 四维向量画像（技能/经验/素质/简历原文）→ 查重（同名/同手机/向量相似）→ 档案问答/语义检索。

**2. AI 智能测评与能力研判（2 分）◎**：题库/组卷/在线作答 → 自动判分 → 能力雷达 → 等级动态评级，结果回写人才等级供匹配排序使用。

**3. AI 岗位-人才精准匹配（3 分）★★★（深度讲，本模块评分点）**
- **岗位智能解析**：手动录入 / 上传岗位说明书（PDF/DOCX/TXT/MD/图片）→ AI 拆解 任职要求/技能标准/学历/年限/综合素质 六大维度 → 生成标准化需求标签（parsed_json 持久化，可重复读取）；LLM 不可用时规则兜底；
- **双向精准匹配**：岗位→人才（招聘视角）与 人才→岗位（人找工作/盘点视角）双向；流程＝岗位画像向量 → Milvus 语义召回 → **硬过滤**（学历门槛/经验年限/必备技能，信息缺失默认放行防误杀）→ **四维软加权** 综合分 0-100（skill×0.5+degree×0.15+years×0.15+quality×0.2），**高分优先推送**（TopK 推荐 + 自动触发空缺补位）；脏向量（缺【人才id】标记）自动跳过，杜绝把 Milvus 自增 id 冒充人才 id；
- **匹配解释可视化**：结果带 dimension_json（四维分落库），页面雷达图 + 得分进度条 + 自然语言"为什么是 86 分"，支持刷新重新生成；
- **岗位预警**：储备/空缺预警与保温管理（见模块四第 7 点之外的储备闭环，讲稿归入匹配），形成"匹配→候选→保温→补位→预警"完整闭环；
- **精度 ≥85 口径**：用 HR 人工真值（reference 模式）评估 precision/recall/F1，附可复现脚本 `scripts/matching_eval_ref.py`；开发期同时通过 300 条级用例回归（题库/发起/待测/交卷/报告链路同套用例体系管理）。

**4. AI 个性化智能培训成长（2 分）◎**：短板诊断（源自测评/报告）→ 定制课程（Agent 只推含视频课程）→ 学习进度管控 → 成长轨迹留痕。

**5. 自然语言智能数据决策（3 分）◎**：问数→取数→多维分析→报告→决策建议（Nl2sql + 看板）。

**6. 企业级人才 RAG 智能问答知识库（2 分）◎**：私有化、防幻觉（不编造策略）、分级权限问答。

**7. 多端协同与权限安全体系（3 分）◎**：管理端（Vue3+Element Plus，动态菜单 RBAC）+ 员工端小程序；权限码粒度到接口（如 matching:*），日志审计与数据隔离。

## 附：评委可能追问（岗位匹配模块专属 Q&A）

**Q1 匹配精度 ≥85 怎么保证？**
答：三件事：① 用 HR 人工真值做 reference 评估（P/R/F1，脚本可复现），而非算法自评；② 精度优化四板斧——skill 权重提到 0.5、关键词命中 0.7 压制语义假阳性、零命中只保留 0.3×sim、年限扣分斜率 15/年；③ 硬过滤前置（学历/年限/必备技能）把明显不合格者挡在推荐外。

**Q2 人才向量从哪来？和 T 域什么关系？**
答：匹配用的人才向量是 M 域**自建**：读 T 域写入 MySQL 的结构化字段（tal_talent）→ 拼【人才id|学历|经验|技能】标记文本 → bge-m3 → Milvus talent_vec；T 域的四维向量/RAG 问答我们不读不调；MinIO 不参与匹配链路。

**Q3 向量更新了怎么办（冷启动/数据变更）？**
答：批量用 `scripts/vectorize_talents.py --drop` 重建（幂等），单岗位可 `POST /positions/{id}/vector` 即时补向量；档案重建后需重跑匹配对齐 talent_id，防 stale（本项目有真实清障实操）。

**Q4 为什么会推一个技能完全不匹配的人（假阳性）？**
答：老版本 skill 只占 0.4 且零命中仍兜底 30 分，会让"语义像"的人混入；已通过命中权重 0.7+零命中压分修复；硬过滤的 mandatory_skills 再兜一层。

**Q5 预警会不会刷屏打扰？**
答：不会。24h 同岗位同清单去重；清单变化（新晋高分/保温变化）才允许重推；推送定向 HR 用户而非全员；缺编 N 人只推 Top min(N,5)。

**Q6 匹配分的四维是实时还是快照？**
答：维度分是**发起匹配时的快照**（存 dimension_json），保证解释和历史可比；列表按"能力等级"等排序时若用人才最新研判字段则是实时 JOIN——两个口径在产品上区分标注。
