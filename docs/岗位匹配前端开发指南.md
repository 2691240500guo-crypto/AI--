# 岗位匹配域前端开发指南

> 面向：接手 admin_web 前端开发的同学
> 后端岗位匹配域（M 域）已全部就绪，前端只需照本文档 + 后端代码对接即可。
> 后端代码位置：`app/routers/matching.py`（接口）、`app/services/matching.py`（算法）、`app/models/matching.py`（数据表）、`app/schemas/matching.py`（字段定义）。

---

## 1. 技术栈与工程约定（必须遵守）

前端项目 `admin_web/` 已有约定，新代码必须保持一致：

| 项 | 约定 |
|---|---|
| 框架 | Vite + Vue 3（`<script setup>`）+ Element Plus |
| HTTP 封装 | `src/utils/request.js`（axios 实例，已处理 token/401 续期/统一报错） |
| API 模块 | 每个业务域一个文件放 `src/api/xxx.js`，导出函数 |
| 页面 | 放 `src/views/xxx/`，一个业务一个 .vue |
| 路由 | `src/router/index.js` 注册 |
| 参考样板 | `src/api/user.js`（API 写法）、`src/views/system/role.vue`（页面写法） |

## 2. 接口调用规范（后端约定，前端必须按此解析）

### 2.1 统一响应格式

所有接口返回 `{code, message, data}`：

```json
{ "code": 0, "message": "ok", "data": { } }
```

- `code === 0` 表示成功，取 `data` 使用
- `code !== 0` 表示业务失败（HTTP 状态仍是 200），`message` 是给用户看的错误提示
- `request.js` 已自动拦截：`code !== 0` 会弹 ElMessage 并 reject，**页面里只需要处理成功分支**（`res.data`）

### 2.2 鉴权

- 登录后 token 自动带在请求头（`Authorization: Bearer <token>`），无需额外处理
- 岗位匹配接口权限码：**`matching:*`**（后端路由统一校验）。前端要在菜单/角色里给账号配 `matching:*` 权限，否则接口返回无权限

### 2.3 分页格式

列表接口请求参数：`page`（从 1 起）、`page_size`（默认 20）

返回结构（`paged_result`）：

```json
{
  "code": 0,
  "data": {
    "items": [ ... ],
    "meta": { "page": 1, "page_size": 20, "total": 35, "total_pages": 2 }
  }
}
```

前端用 `el-pagination`，取 `res.data.items` 渲染表格、`res.data.meta.total` 做总条数。

## 3. 后端接口契约（13 个接口，全部已实现）

统一前缀：`/matching`，完整 URL 前加 `/api`（如 `/api/matching/positions`）。

### 3.1 岗位管理（页面：岗位管理）

| 方法 | 路径 | 说明 | 关键参数 |
|---|---|---|---|
| GET | `/matching/positions` | 岗位列表 | keyword（名称/编码模糊）、dept_id、status、page、page_size |
| POST | `/matching/positions` | 新建岗位 | body：见下方字段表 |
| GET | `/matching/positions/{id}` | 岗位详情 | 路径参数 id |
| PUT | `/matching/positions/{id}` | 更新岗位 | body 部分字段 |
| DELETE | `/matching/positions/{id}` | 删除岗位 | 有匹配结果时后端拒绝（提示改停用） |
| POST | `/matching/positions/{id}/vector` | 岗位画像向量化 | 触发 bge-m3 embedding 写入 Milvus |

岗位字段（创建/更新 body）：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| name | string | ✅ | 岗位名称 |
| code | string | ✅ | 岗位编码（全局唯一） |
| sys_position_id | int | 否 | 对应基础岗位 |
| dept_id | int | 否 | 所属部门 |
| headcount | int | 否 | 编制人数，默认 0 |
| filled | int | 否 | 已到岗人数，默认 0 |
| status | int | 否 | 1 启用 / 0 停用，默认 1 |
| description | string | 否 | 岗位说明书（**匹配画像的输入源，尽量填完整**） |

### 3.2 匹配规则（页面：规则配置）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/matching/rules` | 规则列表 |
| POST | `/matching/rules` | 新建规则 |

规则字段：`name`（规则名）、`rule_json`（权重对象，如 `{"skill":0.4,"degree":0.2,"years":0.2,"quality":0.2}`）、`status`（1/0）。

### 3.3 匹配执行与结果（页面：匹配结果）

| 方法 | 路径 | 说明 | 关键参数 |
|---|---|---|---|
| POST | `/matching/match` | 执行双向匹配 | body：`talent_ids`（空=全部）、`position_ids`（空=全部）、`rule_id`（空=默认规则）、`top_k`（召回量，默认 10） |
| GET | `/matching/results` | 匹配结果列表 | talent_id、position_id、min_score、page、page_size |
| GET | `/matching/result/{id}/explain` | 匹配解释（LLM 生成） | 路径参数 id |

匹配结果字段（`match_result`）：`talent_id`、`position_id`、`score`（0-100）、`dimension_json`（各维度得分）、`explain`（解释）、`rank`（同岗位内名次）、`status`（0 候选 / 1 推荐 / 2 录用）。

### 3.4 预警（页面：预警中心）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/matching/alerts` | 预警列表（可传 position_id 过滤） |
| POST | `/matching/alerts/generate` | 手动生成预警（空缺 + 储备） |

预警字段：`match_id`、`type`（reserve 储备 / vacancy 空缺）、`target_user`、`message_id`、`created_at`。

## 4. 示例代码（照抄即可跑通）

### 4.1 API 封装 `src/api/matching.js`

```js
import http from '@/utils/request'

// ===== 岗位管理 =====
export function listPositions(params) {
  return http.get('/matching/positions', { params })
}
export function getPosition(id) {
  return http.get(`/matching/positions/${id}`)
}
export function createPosition(data) {
  return http.post('/matching/positions', data)
}
export function updatePosition(id, data) {
  return http.put(`/matching/positions/${id}`, data)
}
export function deletePosition(id) {
  return http.delete(`/matching/positions/${id}`)
}
export function vectorizePosition(id) {
  return http.post(`/matching/positions/${id}/vector`)
}

// ===== 匹配规则 =====
export function listRules() {
  return http.get('/matching/rules')
}
export function createRule(data) {
  return http.post('/matching/rules', data)
}

// ===== 匹配执行与结果 =====
export function runMatch(data) {
  return http.post('/matching/match', data)
}
export function listResults(params) {
  return http.get('/matching/results', { params })
}
export function getExplain(id) {
  return http.get(`/matching/result/${id}/explain`)
}

// ===== 预警 =====
export function listAlerts(params) {
  return http.get('/matching/alerts', { params })
}
export function generateAlerts(params) {
  return http.post('/matching/alerts/generate', params)
}
```

### 4.2 岗位列表页骨架 `src/views/matching/position.vue`

```vue
<script setup>
import { onMounted, reactive, ref } from 'vue'
import { ElMessage, ElMessageBox } from 'element-plus'
import { createPosition, deletePosition, listPositions, updatePosition, vectorizePosition } from '@/api/matching'

const rows = ref([])
const loading = ref(false)
const total = ref(0)
const query = reactive({ page: 1, page_size: 20, keyword: '' })
const dialog = reactive({ visible: false, editing: false })
const formRef = ref()
const form = reactive({ id: null, name: '', code: '', dept_id: null, headcount: 0, filled: 0, status: 1, description: '' })
const rules = {
  name: [{ required: true, message: '请输入岗位名称', trigger: 'blur' }],
  code: [{ required: true, message: '请输入岗位编码', trigger: 'blur' }]
}

async function load() {
  loading.value = true
  try {
    const res = await listPositions(query)
    rows.value = res.data.items
    total.value = res.data.meta.total
  } finally {
    loading.value = false
  }
}

function openCreate() {
  Object.assign(form, { id: null, name: '', code: '', dept_id: null, headcount: 0, filled: 0, status: 1, description: '' })
  dialog.editing = false
  dialog.visible = true
}
function openEdit(row) {
  Object.assign(form, row)
  dialog.editing = true
  dialog.visible = true
}
async function save() {
  await formRef.value.validate()
  if (form.id) await updatePosition(form.id, form)
  else await createPosition(form)
  ElMessage.success('已保存')
  dialog.visible = false
  load()
}
async function del(row) {
  await ElMessageBox.confirm(`确定删除岗位「${row.name}」？`, '提示', { type: 'warning' })
  await deletePosition(row.id)
  ElMessage.success('已删除')
  load()
}
async function vec(row) {
  await vectorizePosition(row.id)
  ElMessage.success('向量化完成')
}

onMounted(load)
</script>

<template>
  <el-card>
    <div class="bar">
      <el-button type="primary" @click="openCreate">新增岗位</el-button>
      <el-input v-model="query.keyword" placeholder="名称/编码" style="width:200px;margin-left:12px" @keyup.enter="query.page = 1; load()" />
      <el-button style="margin-left:8px" @click="query.page = 1; load()">查询</el-button>
    </div>
    <el-table v-loading="loading" :data="rows" border stripe>
      <el-table-column prop="name" label="岗位名称" />
      <el-table-column prop="code" label="编码" />
      <el-table-column prop="headcount" label="编制" width="80" />
      <el-table-column prop="filled" label="已到岗" width="80" />
      <el-table-column label="状态" width="80">
        <template #default="{ row }">
          <el-tag :type="row.status === 1 ? 'success' : 'info'">{{ row.status === 1 ? '启用' : '停用' }}</el-tag>
        </template>
      </el-table-column>
      <el-table-column label="操作" width="220">
        <template #default="{ row }">
          <el-button link type="primary" @click="openEdit(row)">编辑</el-button>
          <el-button link type="warning" @click="vec(row)">向量化</el-button>
          <el-button link type="danger" @click="del(row)">删除</el-button>
        </template>
      </el-table-column>
    </el-table>
    <el-pagination style="margin-top:12px" layout="total, prev, pager, next" :total="total"
      v-model:current-page="query.page" :page-size="query.page_size" @current-change="load" />
  </el-card>

  <el-dialog v-model="dialog.visible" :title="dialog.editing ? '编辑岗位' : '新增岗位'" width="560px">
    <el-form ref="formRef" :model="form" :rules="rules" label-width="90px">
      <el-form-item label="岗位名称" prop="name"><el-input v-model="form.name" /></el-form-item>
      <el-form-item label="岗位编码" prop="code"><el-input v-model="form.code" /></el-form-item>
      <el-form-item label="编制人数"><el-input-number v-model="form.headcount" :min="0" /></el-form-item>
      <el-form-item label="已到岗人数"><el-input-number v-model="form.filled" :min="0" /></el-form-item>
      <el-form-item label="状态">
        <el-switch v-model="form.status" :active-value="1" :inactive-value="0" />
      </el-form-item>
      <el-form-item label="岗位说明书"><el-input v-model="form.description" type="textarea" :rows="4"
        placeholder="尽量写全职责/技能要求，是匹配画像的输入源" /></el-form-item>
    </el-form>
    <template #footer>
      <el-button @click="dialog.visible = false">取消</el-button>
      <el-button type="primary" @click="save">保存</el-button>
    </template>
  </el-dialog>
</template>
```

> 其余三个页面（规则配置、匹配结果、预警中心）结构相同，照岗位页改表格列和表单即可，接口已在 4.1 封装好。

| 页面 | 路由建议 | 对应接口 | 关键交互 |
|---|---|---|---|
| 岗位管理 | `/matching/positions` | 3.1 全部 | CRUD + 「向量化」按钮 + 状态筛选 |
| 规则配置 | `/matching/rules` | 3.2 | 规则列表 + 权重 JSON 编辑 |
| 匹配结果 | `/matching/results` | 3.3 | 按岗位/人才筛选，「执行匹配」按钮 + 「查看解释」按钮 |

菜单/权限：在系统管理 → 菜单里加「岗位匹配」目录，下面挂 4 个页面，权限码统一挂 `matching:*`，再分配给角色。

## 6. 注意事项

1. **status 字段语义**：岗位 status（1 启用/0 停用）；匹配结果 status（0 候选/1 推荐/2 录用），页面上用不同颜色 tag 区分。
2. **删除限制**：岗位已有匹配结果时后端拒绝删除（提示改停用），前端要捕获该提示（request.js 已自动弹 ElMessage）。
3. **向量化依赖 Milvus/Ollama**：接口可能返回"检查 Milvus/Ollama 服务"错误，前端展示 message 即可，不用特殊处理。
4. **匹配是异步重算**：`POST /matching/match` 会更新/新增 match_result，已推荐/录用的记录不会被覆盖，前端重跑匹配后要刷新结果列表。
5. **解释按钮**：`GET /result/{id}/explain` 首次调用会调 LLM 生成（可能几秒），建议按钮加 loading；已生成的解释直接返回不重复生成。
6. **分页字段**：务必用 `res.data.items` + `res.data.meta.total`，不要用 `res.data.records`（后端字段就是 items/meta）。
7. **代码边界**：前端只新增 matching 相关文件（api/matching.js、views/matching/、路由+菜单），不要改动现有 auth/user/role 等模块文件；如需修改公共组件先和后端负责人确认。
