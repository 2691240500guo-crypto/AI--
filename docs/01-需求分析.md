## 一、项目概述

### 1.1 项目背景
建设 AI 数字化人才平台，以 AI 能力（大模型、向量检索、多 Agent 协同）赋能人才管理全流程，覆盖**档案、测评、匹配、培训、数据决策**五大业务域，并配套系统权限、消息通知、审计安全、移动端体验。

### 1.2 项目约束
| 项 | 约束 |
|---|---|
| 团队规模 | 6 人（P1–P6） |
| 交付节奏 | 三日冲刺 MVP → 后续迭代 |
| 技术栈 | 移动端 H5（Vue3 响应式页面）；管理端 Vue3+Element Plus；后端 Python3.11+FastAPI |
| 数据库 | MySQL 8 + Redis |
| AI 引擎 | Ollama（推理/Embedding）+ Milvus（向量）+ MinIO（对象）+ LangChain/LangGraph（编排/RAG） |

### 1.3 验收口径
> **功能必须实现（硬），Agent 可以不够聪明（软）。** 验收只卡"有没有、跑不跑得通、能不能演示"，不卡"灵不灵"。
> 六条核心验收线：登录鉴权 → 档案入库 → 测评出报告 → 岗位匹配 → 培训推送 → NL2SQL 问数；多 Agent 协同至少一条闭环可演示。

### 1.4 系统总体架构
```
┌─────────────────────────────────────────────────────────────┐
│ 客户端：移动端 H5（Vue3 响应式，员工/测评/学习）│ 管理端 Vue3+ElementPlus（HR/管理员） │
├─────────────────────────────────────────────────────────────┤
│                API 网关 / 统一入口 /api/v1                    │
├─────────────────────────────────────────────────────────────┤
│              后端 fastapi：router → service → dao → model     │
│  auth │ talent │ assessment │ matching │ training │ analytics │
│  message │ audit │ system │ ai                              │
│  AI 引擎：LangChain(RAG) · LangGraph(多Agent) · 五大Agent     │
│  横切：JWT认证 · RBAC权限 · Pydantic校验 · 审计留痕 · 限流     │
├─────────────────────────────────────────────────────────────┤
│  数据层：MySQL(主) · Redis(会话/限流) · Milvus(向量) · MinIO(文件) · Ollama(推理) │
└─────────────────────────────────────────────────────────────┘
```
**分层原则**：严格 `router → service → dao → model` 单向依赖，禁跨层访问数据库。

### 1.5 通用设计规约
| 规约 | 约定 |
|---|---|
| 统一响应 | `{code:0,msg:"ok",data:{…},meta:{page,page_size,total}}` |
| 错误码 | 0成功 / 40100未认证 / 40101过期 / 40300无权限 / 40001参数错 / 40002业务错 / 40400不存在 / 42900限流 / 50000异常 |
| 鉴权 | `Authorization: Bearer <token>`；登录返 access+refresh，`/auth/refresh` 续期 |
| 分页 | `page`(默认1) `page_size`(默认20) → `meta` |
| 枚举 | 一律走数据字典 `sys_dict_item`，接口返 `value`，前端按 `type_code` 映射 |
| 时间 | ISO8601，UTC+8 |
| 脱敏 | 证件号/电话/邮箱默认脱敏返回，is_super 明文 |
| 留痕 | 所有写操作经审计中间件写 `sys_operation_log` |

### 2.3 角色与权限体系（2026-09-02 更新）

> 合并原 super_admin/admin 为单一最高管理员，新增 backend（后端运维）与 employee（企业员工）角色。

| 角色编码 | 角色名 | 登录端 | 定位 | 数据范围 |
|---------|--------|--------|------|---------|
| `admin` | 高级管理员 | 管理端 | 权限最高：系统管理+业务全模块+角色授权+全部员工账号 | 全局（is_super 短路） |
| `hr` | HR 角色 | 管理端 | 业务管理：档案/测评/培训/岗位/本部门员工账号 | 全局业务 |
| `backend` | 后端运维 | 管理端 | 系统配置/字典/日志/监控 | 系统域 |
| `employee` | 企业员工 | 小程序 | 自助：学习/测评/培训/档案/AI（仅本人） | 仅本人（talent_id 隔离） |

**登录分流**：管理端 `POST /auth/login`（user_type=admin + 角色 ∈ {admin, hr, backend}）；小程序 `POST /auth/employee-login`（user_type=employee + 角色=employee）。
**端隔离**：token 写入 client_type（admin/app），`require_client(types)` 校验，跨端调用拒绝。
**数据隔离**：employee 接口一律从 token 取 talent_id，不信任前端传参。

## 十四、五大 Agent 协同链路（三日必通至少一条）
| Agent | 输入 | 输出 | 核心链路 | 技术栈 | 协同 |
|-------|------|------|---------|--------|------|
| ①简历解析 | 简历文件 | 结构化档案+标签 | Loader→Ollama抽取→入库→向量 | LangChain+Ollama+Milvus | →向量(T-7,供③) |
| ②测评分析 | 成绩+履历 | 雷达/短板/评级/报告 | 成绩→Ollama→报告→回写T等级 | LangChain+Ollama | →Agent④(A-7) |
| ③岗位匹配 | 人才+岗位向量 | 匹配度+解释推荐 | Milvus召回→加权→排序 | Milvus+Ollama | ←①向量→M-5 |
| ④培训推送 | 短板+岗位能力 | 学习计划+推送 | 短板→选课→计划→MSG | LangGraph+Ollama | ←②闭环 |
| ⑤NL2SQL | 自然语言 | SQL+结果+图表 | NL→SQL→执行→出图 | LangChain+受限执行 | →D-4导出 |

**三大闭环**：
- **链路A（成长闭环）**：`T-6入库→A-3发起→A-6(报告)→A-7→TR-3(计划)→TR-2学习→复测`
- **链路B（人岗闭环）**：`T-7向量+M-2向量→M-3匹配→M-5预警→MSG/D看板`
- **链路C（问数闭环）**：`D-3直查T/A/TR/M→出图→D-4报表`
