# 3 分钟答辩讲稿：从简历解析到岗位匹配

> 使用说明：全文约 900 字，正常语速（约 250 字/分钟）≈ 3 分钟。
> 段落前标注了大致时间点和节奏提示。讲稿含【Q&A 预判】附录，供评委提问备用。

---

## 开场（0:00–0:20）

各位老师好。我负责的这条链路，解决的问题是：**把一份原始简历，变成系统能理解、能检索、能打分的"人才资产"，最终实现岗位与人才的智能匹配**。我分四步讲：简历解析、画像与向量化、岗位匹配、结果闭环。

## 第一步：简历解析 —— 让大模型把"人话"读成"数据"（0:20–1:00）

简历是自由文本，机器没法直接用。我们上传简历后，先做文本抽取得到原文；**关键一步是调用大模型**，让它在固定 JSON 结构下抽取字段：姓名、学历、年限、技能等 8 大主档字段，还有亮点、短板、适配岗位、潜力评级这些"评价性"内容。为了让模型不编造，我们做了两件事：一是**抽不到就填空，绝不臆造**；二是**只填空缺项，人工填过的值不被覆盖**。

一次抽取完成后，还会做第二次大模型调用，把结构化结果润色成"优势、短板、适配岗位、发展潜力"四段自然语言报告，存在 AI 报告表里，可追溯。

这里要强调一个工程点：**解析失败不阻塞入库**——大模型挂了，人才照样进库，只是结构化字段为空，报告表里记录失败原因，可手动重跑。这保证了整条链路不会因为外部 AI 抖动而断掉。

## 第二步：画像与向量化 —— 从"能看懂"到"能检索"（1:00–1:40）

解析结果落在 MySQL，但它只能被关系查询命中。要让系统支持"语义检索"，我们需要向量。

做法是：**代码从库里读档案，拼成画像文本**——注意，这一步是纯代码字符串拼接，不是大模型生成的。画像文本最前面有一段结构化标记，叫 meta 头，形如"人才id 35，硕士学历，3 年经验，技能 Python、Java"。它是匹配时做硬性过滤的契约。

然后调用 **bge-m3 向量模型**，把画像文本转成 1024 维向量，按"技能、经验、素质、简历原文"四个维度 upsert 进 Milvus。向量库的主键直接用人 id，天然幂等，档案一变就能覆盖更新。上传、编辑、合并人才档案都会自动触发向量刷新；存量数据用脚本一次性回灌。

## 第三步：岗位匹配 —— 召回 + 硬过滤 + 软加权（1:40–2:30）

岗位侧同样建画像向量。匹配时我们做三层：

第一层，**向量召回**。用岗位向量在人才简历向量里粗召回一批候选——这一步解决"语义像不像"。

第二层，**硬性过滤**。召回文本里带着 meta 头，我们用正则解析出学历、经验、技能，凡是硬性条件不满足的，直接剔除，不参与打分。这就避免了"向量看着像、其实学历年限不符"的误配。

第三层，**软加权打分**。技能维度用向量相似度和关键词命中率融合，再按"技能、学历、年限、素质"四个维度的规则权重加权，得到 0 到 100 的匹配分，排序后取每个岗位的前若干名。

整个打分过程**全部是规则和 SQL**，大模型不参与决策——保证可解释、可复现。系统还支持两种入口：一种是一键批量匹配；另一种是"匹配 Agent"对话，用户用自然语言描述需求，由大模型把需求解析成结构化条件，再走同样的召回和过滤，最后用大模型生成人话回复。

## 第四步：结果与闭环（2:30–2:50）

匹配结果落库后，可以一键生成**匹配解释**：读各维度得分，让大模型写一段 80 字以内的推荐依据，比如"技能维度突出，学历年限达标，综合 88 分，建议推荐"。大模型不可用时自动降级成规则化模板。最后是推送记录和储备预警，按分数阈值和去重窗口触发。

## 总结（2:50–3:00）

一句话总结：**大模型负责"读懂"——解析简历、理解自然语言需求、生成解释；向量负责"召回"——语义相似检索；规则负责"把关"——硬过滤与打分。** 三者各司其职，而且每一处大模型都有规则兜底，保证系统在 AI 服务波动时依然可用、结果可追溯。谢谢各位老师，请批评指正。

## 附录：Q&A 预判

**Q1：人才向量是简历解析大模型生成的吗？**
不是。解析产出的是结构化 JSON 和报告，落在 MySQL；向量是解析落库之后，代码拼画像文本、再调 bge-m3 向量模型生成的"派生产物"。两者模型不同、产物形态不同，且失败互相不影响。

**Q2：向量检索既然是"相似"，硬性条件怎么保证？**
靠 meta 头。它把学历、年限、技能等硬条件跟着向量一起存进 text 字段，召回后用正则解析，硬过滤不满足的候选直接剔除，再进软加权。

**Q3：整个流程用了几处大模型？挂了怎么办？**
对话式大模型三处：简历解析、Agent 需求解析、解释生成，全部有规则兜底或失败记录；向量模型一处：bge-m3，负责一切 embedding。打分、过滤、阈值、落库均为规则实现。单点故障不阻塞人才入库和结果生成。

**Q4：匹配规则权重怎么定？**
默认规则为技能 0.5、学历 0.15、年限 0.15、素质 0.2，把"技能对不对"的话语权放大，避免"学历高年限长但技能完全不相关"的人挤到前排；规则存 match_rule，可按岗位调整。
