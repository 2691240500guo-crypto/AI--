- `docs/manual_test/岗位说明书-AI应用算法工程师（大模型方向）.md`
- `docs/manual_test/简历-欧阳询-大模型应用算法工程师.md`

## ① 新增岗位（验证 自动解析 + 自动向量化）
1. 岗位管理 → 新增岗位：岗位名称填「AI 应用算法工程师（大模型方向）」、编码 `AI-APP-2026-01`、部门任选、编制 3/到岗 1、状态**启用**。
2. 岗位说明书：点「导入说明书文件」选上面的 .md，或直接粘贴内容 → 保存。
3. 预期：保存按钮约 5~15 秒返回（自动跑 LLM 解析 + bge-m3 向量化）。
4. 验证点：
   - 后端日志出现 [position] 相关；
   - 该岗位「编辑」弹窗里应能看到解析出的标签（若有展示）；
   - 重跑反向匹配或发起匹配能召回该岗位。
5. 反例验证（可选）：新建一个**停用**或**无说明书**的岗位 → 保存应为秒回、无向量。

## ② 上传简历（验证 解析 → 人才画像 → 自动向量 → 自动匹配）
1. 人才档案 → 导入档案 → PDF 简历智能解析 → 选上面的 `简历-欧阳询….md`（或先另存为 .txt）→ 上传。
2. 预期：约 5~15 秒解析完成生成档案「欧阳询」，字段自动填入（学历=硕士、经验≈3~5年、技能列表）。
3. 验证点：
   - 档案详情：姓名/学历/年限/技能/当前职位/公司正确；
   - 系统自动触发匹配，该人才在多个岗位下生成 match_result（"自动匹配"机制，若未启用可手动点发起匹配）；
   - 用 Agent 对话「欧阳询适合什么岗位」应列出适配岗位并按匹配度排序。
4. 反例验证（可选）：再传一份同名「欧阳询」但不同学历/经验 → 重名聚合展示。

## ③ 全链路收口
1. 「AI 应用算法工程师」岗位对「欧阳询」做一次匹配解释（四维 + LLM 文案）。
2. 若匹配分 ≥80 → 触发一次储备预警生成，应看到该人才入储备预警。

## 预期关键数据
- 学历等级映射：硕士(3) ≥ 岗位要求硕士(3) → 学历维度 ≥90；
- 经验：3 年以上达标；
- 技能：Python/RAG/LangGraph/FastAPI/Milvus 全覆盖 → 技能维度接近满分；
- 该人才在 AI 应用岗位应排进 Top 3。
