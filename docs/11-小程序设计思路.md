# 小程序端设计思路（员工自助客户端）

> 版本：v1.0　日期：2026-09-02
> 定位：AI 数字化人才平台的「员工自助客户端」，与管理端形成"管理 / 使用"双端闭环

---

## 1. 整体定位

### 1.1 一句话定位

> **管理端管"人"，小程序端服务"人"** —— 管理员/HR 在管理端完成人才、简历、岗位、测评、培训的**管理与配置**；员工在小程序端完成**学习、测评、培训、查看档案**等自助操作。

### 1.2 双端分工

| 端 | 使用者 | 核心职责 | 典型动作 |
|----|--------|---------|---------|
| **管理端**（admin_web / 5173） | 管理员、HR | 管理配置 | 维护人才档案、解析简历、管理岗位、发起测评、配置培训、查看报表 |
| **小程序端**（miniapp / 5174 / 微信小程序） | 企业员工 | 自助使用 | 登录、在线学习、智能测评、智能培训、查看我的档案、AI 助手 |

### 1.3 设计原则

1. **员工零门槛**：登录即用，界面移动端友好，操作不超过 3 步
2. **只看自己的**：员工数据严格限定本人（档案/测评/学习进度/消息），不可见他人数据
3. **与管理端联动**：小程序的行为结果回流到管理端（测评成绩→HR 视角、学习进度→培训联动）
4. **M 域能力延伸**：Agent 智能匹配以"人才→岗位"（我适合什么岗位）视角开放给员工

## 2. 信息架构（页面结构）

```
小程序（tabBar 5 个主页面）
├── 首页（index）          员工工作台：待办/学习入口/消息提醒
├── 在线测评（assessment） 测评列表 → 作答（quiz）→ 测评报告
├── 在线学习（study）      课程列表 → 视频学习 → 学习进度
├── 消息（message）        系统通知/测评提醒/培训通知
└── 我的（mine）           个人中心：档案/设置/退出

子页面（非 tabBar）
├── 登录（login）          员工账号登录
├── 我的档案（profile）    本人人才档案（来自 T 域）
├── AI 助手（ai）          NL2SQL / 智能问答
└── Agent 智能匹配（matching/agent）  人才→岗位反向匹配
```

## 3. 核心功能模块

### 3.1 在线学习（学习域）
- **课程列表**：按岗位/技能分类浏览课程
- **视频学习**：在线播放、记录学习进度
- **学习进度**：我的学习轨迹、完成率
- **培训联动**：测评短板 → 推荐对应课程（C 域联动）

### 3.2 智能测评（测评域）
- **测评列表**：展示分配给本人的测评任务（待测/进行中/已完成）
- **在线作答**：单选/多选/判断，倒计时，草稿保存，交卷
- **测评报告**：查看维度得分、雷达图、优劣势分析、评级建议
- **状态流转**：待测 → 作答中 → 已交卷 → 报告已生成

### 3.3 智能培训（培训域）
- **培训计划**：我的培训任务（来自测评短板联动）
- **培训课程**：学习指定课程，完成培训闭环
- **培训记录**：历史培训与完成情况

### 3.4 我的档案（人才档案域）
- 查看**本人**人才档案：基本信息/学历/技能/工作经验/标签
- 来源：T 域 `tal_talent`，员工只读本人记录

### 3.5 Agent 智能匹配（M 域，本域负责）
- **人才→岗位**：员工描述"我适合什么岗位"，Agent 反向匹配输出适配岗位与匹配度
- **岗位浏览**：查看在招岗位（后续扩展：转岗意向）
- 与管理端"岗位→人才"互为镜像，形成双向匹配闭环

### 3.6 AI 助手
- 自然语言问数（NL2SQL）、平台使用问答

## 4. 权限设计（2026-09-02 更新：员工登录走 sys_user 扩展 + employee 角色）

| 能力 | 员工（employee） | 游客（未登录） |
|------|:-----------:|:-------------:|
| 登录（工号/微信 openid） | ✅ | — |
| 在线学习 | ✅ | ◐ 仅公开课程（可选） |
| 智能测评（作答/报告） | ✅（本人） | ❌ |
| 智能培训 | ✅（本人） | ❌ |
| 我的档案 | ✅（本人） | ❌ |
| Agent 匹配（人才→岗位） | ✅ | ❌ |
| 消息 | ✅（本人） | ❌ |
| AI 助手 | ✅ | ❌ |

**员工账号设计（不新建表，扩展 sys_user）**：
- `emp_no`（工号，唯一索引）：小程序工号登录
- `talent_id`（FK → tal_talent）：本人数据隔离锚点，接口一律从 token 取，不信任前端传参
- `user_type`（admin/employee）：登录入口分流，管理端 `/auth/login` 只接受 admin，小程序 `/auth/employee-login` 只接受 employee

**三层防护**：
1. 端隔离：请求头 `X-Client-Type: app` + token 端标识，跨端调用拒绝
2. 角色校验：仅 `employee` 角色可登录小程序
3. 数据隔离：接口强制绑定当前登录人 talent_id

## 5. 技术架构

```
┌─────────────────────────────┐
│  小程序端（uni-app）          │
│  Vue3 + Pinia + uni.request │
└─────────────┬───────────────┘
              │ X-Client-Type: app + Bearer Token
              ▼
┌─────────────────────────────┐
│  后端 FastAPI（/api/v1）     │
│  端隔离校验 → 角色校验 → 数据过滤 │
├──────────┬────────┬─────────┤
│ 测评域(C) │ 学习域 │ 培训域  │
│ 档案域(T) │ M 域   │ 消息域  │
└──────────┴────────┴─────────┘
              │
      MySQL / Milvus / 硅基流动
```

### 关键实现点
- **H5 开发**：`npm run dev:h5` → 5174，vite 代理 `/api` → 8000
- **微信小程序**：`npm run dev:mp-weixin`，请求直连后端（需公网可达或内网穿透）
- **依赖锁定**：vue@3.4.21 / pinia@2.1.7 / @vue/shared@3.4.21（防依赖树错位白屏）

## 6. 与管理端的联动闭环

```
HR 在管理端发起测评 ──► 员工小程序收到待测通知
员工完成作答 ──► 报告生成 ──► HR 管理端查看成绩统计
测评发现短板 ──► 培训联动 ──► 员工小程序收到培训任务
员工学习完成 ──► 进度回流 ──► HR 管理端查看学习完成率
```
