# 权限设计文档（ai_talent 平台）

> 版本：v1.0　日期：2026-09-02　作者：岗位匹配域（M 域）
> 适用范围：管理端（admin_web / 5173）+ 客户端（miniapp / 5174 / 微信小程序）全平台权限体系

---

## 1. 设计目标

1. **三种身份，三层权限**：管理员（含 HR）全量管理、企业员工自助使用、游客仅公开浏览。
2. **RBAC 模型**：用户 → 角色 → 菜单/权限码，与现有 `sys_user/sys_role/sys_menu` 体系一致，不改表结构。
3. **三端隔离**（管理端 / 客户端 / 游客端）通过「端标识 + 角色权限码 + 数据归属过滤」三层实现。
4. **最小改动**：复用现有 `require_permission(perm)` 校验器与 `sys_role_menu` 分配机制。

---

## 2. 角色定义（2026-09-02 更新：super_admin 与 admin 合并，新增 backend/employee）

| 角色编码 | 角色名 | 定位 | 登录端 | 数据范围 |
|---------|--------|------|--------|---------|
| `admin` | 高级管理员 | 系统最高权限，全功能全数据（合并原 super_admin/admin） | 管理端 | 全局（is_super 直接放行） |
| `hr` | HR 角色 | 人力资源业务管理（岗位/档案/测评/培训 + 本部门员工账号） | 管理端 | 全局（按菜单授权） |
| `backend` | 后端运维 | 系统配置/字典/日志/监控 | 管理端 | 系统域（按菜单授权） |
| `employee` | 企业员工 | 员工自助（本人档案/测评/学习/消息/AI） | 小程序 | **仅本人数据**（talent_id 隔离） |
| （无角色） | 游客 | 未登录公开浏览 | 浏览器直接访问 | 仅公开页面 |

> `employee` / `backend` 已建库（2026-09-02）；`hr` 已有（15 项菜单权限）。

## 4. 数据权限（行级隔离）

| 数据对象 | admin / hr | employee | 实现方式 |
|---------|-----------|---------|---------|
| 人才档案 `tal_talent` | 全库 | 仅本人（`talent_id == 当前用户`） | 接口强制绑定当前登录人 |
| 测评结果 `asm_result` | 全部 | 仅本人 | 查询条件加 `talent_id` |
| 消息 `sys_message` | 全部 | 仅本人（收件人=我） | 按接收人过滤 |
| 学习进度 | 全部 | 仅本人 | 按用户过滤 |
| 岗位 / 匹配结果 | 全部 | 不开放（员工在客户端走"人才→岗位"） | 管理端接口不挂到客户端 |

**规则**：员工端接口一律**不接收前端传入的 talent_id**，从 token 解析当前用户后映射到其关联的人才记录（`sys_user.openid` 或 user→talent 关联），防止越权查询他人数据。

## 5. 接口级权限（perm 权限码）

复用 `app/core/deps.py` 的 `require_permission(perm)` 校验器（超管 `is_super` 自动放行）。

### 5.1 需要加权限码的接口（当前缺校验）

| 接口 | 权限码建议 | 角色 |
|------|-----------|------|
| `POST /matching/positions`（岗位新增） | `matching:position:create` | admin / hr |
| `PUT/DELETE /matching/positions/{pid}` | `matching:position:update/delete` | admin / hr |
| `POST /matching/positions/{pid}/vector` | `matching:position:vector` | admin / hr |
| `POST /matching/rules`（规则配置） | `matching:rule:manage` | admin / hr |
| `POST /matching/agent/parse` / `run` | `matching:agent:match` | admin / hr |

| 系统管理全部接口 | `system:*` | admin（hr 不授） |

### 5.2 员工端接口（客户端使用，仅需登录即可）

| 接口 | 说明 | 数据过滤 |
|------|------|---------|

## 6. 端隔离（X-Client-Type）

- 管理端请求头：`X-Client-Type: admin`（`admin_web/src/utils/request.js` 统一注入）
- 客户端请求头：`X-Client-Type: app`（`miniapp/src/utils/request.js` 统一注入）
- 后端 `deps.py` 增加 `require_client(types)` 校验器：管理端接口要求 `admin`，客户端接口要求 `app`，token 的 payload 中写入端标识，登录接口按端标识签发。

**效果**：管理端账号登录的 token 无法调用客户端接口，反之亦然；即使泄露 token 也无法跨端操作。

## 7. 前端菜单/路由控制

### 7.1 管理端（admin_web）
- 菜单由后端 `GET /menus/mine` 按角色返回（`sys_menu` + `sys_role_menu`），前端 `layout/index.vue` 已按 `user.menus` 渲染 → **员工不登录管理端**，管理端只有 admin/hr 登录。
- 路由守卫 `router/index.js`：未登录跳 `/login`；无菜单权限的路由拦截（建议增加 `meta.perm` 校验）。

### 7.2 客户端（miniapp）
- `pages.json` 页面无权限配置，登录后在 `App.vue` 校验 token；
- 未登录访问需登录页面 → 跳 `/pages/login/login`；
- 游客仅能访问公开页（如首页 + 登录页），其余页面在 `onShow` 中做登录拦截。

## 9. 关键设计决策记录（ADR）

| 决策 | 选择 | 理由 |
|------|------|------|
| 权限模型 | RBAC（沿用现有 sys_* 表） | 零迁移、复用现有菜单/角色/校验器 |
| 员工数据隔离 | 接口层强制绑定当前登录人 | 比前端隐藏更安全，杜绝越权传参 |
| 端隔离 | 独立 `X-Client-Type` + token 端标识 | 两端账号体系天然隔离，防 token 跨端滥用 |
| 游客 | 仅公开页 + 登录拦截 | 最小暴露面，符合企业内网系统惯例 |
| 超管放行 | `is_super` 短路 | 与现有 `require_permission` 行为一致，不破坏已有逻辑 |

## 10. 风险与待确认

1. **员工身份 ↔ 人才档案映射**：`sys_user` 与 `tal_talent` 的关联字段待确认（建议用 `sys_user.openid` 或新增 `talent_id` 外键），否则"本人数据过滤"无法落地。
2. **hr 与 employee 是否共用一个登录入口**：管理端只给 admin/hr，客户端给 employee，登录接口需按端限制角色。
3. **游客开放范围**：是否开放公开岗位列表/公开课程，需产品确认。
4. **现有接口未加权限码的存量**：需全量盘点（当前只有 admin 菜单全量 + hr 部分），补码期间可能影响联调，建议分批执行。
