## 三、匹配算法核心逻辑

1. **画像向量化**：岗位说明书 → 组装画像文本（含 `【岗位id:x】` 标识）→ bge-m3（1024 维）→ Milvus `position_vec`
2. **向量检索**：岗位向量查 `talent_vec` 召回 top-k → 硬过滤（排除空画像）
3. **软加权算分**（4 维度 × 权重，默认权重见下表）：
   - skill（0.4）：向量相似度×0.7 + 关键词命中率×0.3
   - degree（0.2）/ years（0.2）/ quality（0.2）：MVP 阶段固定中性分 75（二期接 T 域真实数据）
4. **排序落库**：同岗位分数降序生成 rank，`UNIQUE(talent_id, position_id)` 幂等更新，已推荐(1)/录用(2) 不覆盖
5. **解释与预警**：Ollama 生成解释（降级规则化）；空缺（编制未满）/储备（≥80 分）写消息 + 推送日志

## 四、补充说明

- **分层规范**：router → service → dao → model 单向调用，算法全部在 `app/services/matching.py`，路由只做参数校验和响应封装。
- **AI 底座容错**：Ollama/Milvus 不可用时统一抛 `BusinessError(500)`，解释生成单独做降级，不会让接口直接崩。
- **域边界**：仅操作岗位匹配域表（pos_position / match_rule / match_result / match_push_log）；人才数据（tal_talent / talent_vec）属 T 域，本域只读复用，绝不创建/修改。
- **二期规划**：degree/years/quality 接入 tal_talent 真实数据精确计分；岗位画像向量化 → Milvus 的自动化任务（T-P4-01）。
