## 四、后端基建能力

### 4.1 统一响应与全局异常

响应格式：`{code, message, data, path?, type?}`

| 场景 | HTTP | code | 示例 |
|------|------|------|------|
| 成功 | 200 | 0 | `{"code":0,"message":"ok","data":...}` |
| 业务异常 BusinessError | 200 | 业务码 | 400 账号或密码错误 |
| 参数校验失败 | 422 | 422 | `data.errors` 字段明细 |
| HTTP 异常(404/401/403) | 真实状态码 | 同状态码 | 404 用户不存在 |
| 未知异常 | 500 | 500 | Internal server error |

使用：
```python
from app.utils.response import ok, BusinessError
raise BusinessError(400, "业务错误信息")   # 业务层抛异常
return ok({"data": ...})                    # 成功返回
```

### 4.2 统一日志

- 日志文件：**固定 `D:\tanle\ai_talent.log`**（无论从哪个目录启动）
- 使用：`from app.utils.logger import logger; logger.info("...")`
- 日志文件已 gitignore，不提交仓库

### 4.3 审计留痕（操作日志）

- **自动**：所有写操作（POST/PUT/DELETE/PATCH）自动写入 `sys_operation_log`，业务零侵入
- 记录：操作人(user_id/username)、方法、路径、状态码、IP、耗时、请求体（密码自动脱敏为 `***`）
- 查询：管理端「操作日志」页 / `GET /api/v1/audit/logs` / 导出 CSV `GET /api/v1/audit/logs/export`
- 登录记录：`sys_login_log`，管理端「登录日志」页

## 七、动态路由与新增页面

**核心机制**：菜单表(`sys_menu`)是路由的唯一来源。新增页面后，只需在「菜单管理」挂一个菜单，登录后路由自动注册，无需改 `router/index.js`。

约定：
- `component` 字段写相对 `src/views/` 的路径，如 `system/User` → 匹配 `src/views/system/user.vue`（大小写不敏感）
- `type`：1=目录 2=菜单页 3=按钮权限码

流程（开发一个管理端页面）：
1. 在 `src/views/<模块>/` 建页面（照 `system/user.vue` 模板）
2. 在 `src/api/` 建接口封装（照 `api/user.js`）
3. 在「菜单管理」新增菜单（path + component + perm 权限码）
4. 给角色勾选新菜单权限
5. 刷新登录 → 侧边栏出现新菜单 → 点击进入

## 八、如何新增一个业务模块（五步走）

以「人才档案 talent」为例（README 有完整示例）：

```bash
# 1. model：models/talent.py 写 class Talent(Base)，并在 models/__init__.py 导出
# 2. schema：schemas/talent.py 写 Create/Update/Query/Out
# 3. dao：dao/talent.py 继承 BaseDAO 并标注 __model__
# 4. service：services/talent_service.py 写业务逻辑
# 5. router：routers/talent.py CRUD 照抄 user.py，并在 routers/api.py 挂载
```

```python
# routers/api.py 挂载新模块
from app.routers import talent
api.include_router(talent.router, prefix="/talent", tags=["talent"])
```

**横切能力零侵入接入**：
- 权限：路由参数加 `dependencies=[Depends(require_permission("talent:list"))]`
- 审计：已全局自动（写操作自动留痕）
- 消息：`MessageService.send(db, type_code=..., title=..., content=...)`
- AI：调用 `get_rag()` / `get_llm()` 即可

## 九、AI 工具层

工具层四件套在 `app/utils/`，**惰性加载**（未安装对应依赖不影响系统启动）：

### 10.1.1 克隆到指定位置（注意：先 cd 再 clone）

> ⚠️ **`git clone` 会把代码放到"当前所在的目录"下**，它不会自己去找 D 盘或其他盘。
> 想放到哪，就必须**先 `cd` 到那个目录**，再执行 clone。

```powershell
# 例1：克隆到 D 盘根目录（D:\ 下生成 D:\ai_talent\）
cd D:\
git clone https://gitee.com/sjdahk/ai_talent.git

# 例2：克隆到 D 盘某个子目录（如 D:\code\）
cd D:\
mkdir code            # 目录不存在时先建（可选）
cd code
git clone https://gitee.com/sjdahk/ai_talent.git
```

关键点：
- **不用手动 mkdir 项目文件夹** —— `git clone` 会自动用仓库名 `ai_talent` 建文件夹
- **先 `cd` 到目标位置再 clone** —— 在 `C:\Windows\system32` 里 clone 就会放到 C 盘
- 克隆完成后进项目配置环境：
  ```powershell
  cd D:\ai_talent
  copy .env.example .env      # 创建自己的配置（.env 不上传，必须手动复制！）
  pip install -r requirements.txt
  ```
- 日常开发建议直接用现有 `D:\tanle`（已配置好一切）；clone 的副本用于新机器 / 其他同事 / 只读代码。

### 10.4 撤销操作

```bash
# 撤销未提交的修改
git checkout -- <文件>

# 撤销已 add 未 commit
git reset HEAD <文件>

# 撤销最近一次 commit（保留改动）
git reset --soft HEAD~1

# 撤销最近一次 commit（丢弃改动）⚠️ 危险
git reset --hard HEAD~1

# 强制推送（覆盖远程）⚠️ 危险，禁用于 main
git push --force
```

## 十一、常见问题 FAQ

### Q1: `python app/main.py` 报 `ModuleNotFoundError: No module named 'app'`
已修复：main.py 顶部自动注入项目根目录到 sys.path。仍报错说明是从旧代码跑的，`git pull` 更新。

### Q2: 环境里 `jose` 报语法错误 `Missing parentheses in call to 'print'`
装错包了。卸载老包并装正确的：
```bash
pip uninstall jose -y
rm <site-packages>/jose.py   # 手动删残留单文件
pip install "python-jose[cryptography]==3.3.*"
```

### Q3: 日志文件出现在 app 目录而不是根目录
旧代码问题，已修复（logger 固定 `Path(__file__).parents[2]` 定位根目录）。`git pull` 更新。

### Q4: alembic 命令报 GBK 编码错误
Windows 必须加 `PYTHONUTF8=1`：`PYTHONUTF8=1 alembic revision --autogenerate -m "..."`

### Q5: 管理端登录"点了没反应"
- 检查后端是否启动（`http://127.0.0.1:8000/docs` 能开吗）
- 检查浏览器 F12 Console 是否有报错
- 已修复 try/catch 吞错问题，现在会弹具体错误

### Q6: 登录成功但侧边栏空白
旧 layout 无 flex 布局导致菜单高度为 0，已修复。`git pull` + 强制刷新（Ctrl+Shift+R）。

### Q7: 新增页面后点菜单 404
- 确认菜单 `component` 字段与 `src/views/` 下文件路径一致（如 `system/User` → `system/user.vue`）
- 确认角色已勾选该菜单权限（admin 超管默认全开）

### Q8: `npm run build` 报 dist 删除失败（Windows）
沙箱/权限问题，用：`npx vite build --outDir dist_new`，然后手动整理。

### Q9: 密码哈希/登录突然失败
不要直接改 ORM 对象的 `password` 属性来"避免返回密码"——响应靠 schema 控制（UserOut 不含 password）。若误操作，重置：
```python
python -c "from app.core.security import hash_password; import pymysql; ..."
```

### Q10: 从 app 目录启动后生成 dev.db
已修复（config.py 用绝对路径读 .env）。仍出现说明旧代码，`git pull` 更新。
