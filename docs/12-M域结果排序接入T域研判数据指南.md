# M域结果排序接入 T 域研判数据指南

## 一、目的与适用范围

给岗位匹配（M 域）提供一套"结果列表按 T 域研判产物排序"的可执行对接方案，明确：
**T 域负责把哪些研判结果落进公共 MySQL，M 域负责怎么只读这些字段做 SQL 层排序。**

适用场景：匹配结果页（`/matching/results`）按 **能力等级、从业经验、综合评分** 排序；
以及未来把 **适配岗位研判**（fit_positions 白名单）接入匹配的预留契约。
本指南只改 M 域代码 + 新增本文档，不触碰其他域代码。

## 二、总体结论（先说清能做什么）

1. **T 域研判产物分两层**：落库成结构化字段的（`tal_talent` / `tal_talent_report`）→ M 域读表可用；
   实时语义层（四维向量 `talent_skill/exp/quality/resume`、RAG 问答接口）→ M 域**不读不调**，不做排序依据。
2. **三个排序键现状**：

   | 排序键 | 落库字段 | 现状 |
   |--------|---------|------|
   | 能力等级 | `tal_talent.level` | **已有**，M 域排序已实现（JOIN），待 T 域统一枚举口径 |
   | 从业经验 | `tal_talent.years_experience` | **已有**（T 域解析回写的整数字段）；M 域当前排的是匹配达标分，需加"真实年限"排序键 |
   | 综合评分 | `tal_talent_report.quality_score`（建议新列） | **尚无单一数值**，需 T 域定义口径并落库 |

3. **数据流**：T 域写（主档+报告表）→ MySQL → M 域匹配/查询时 SELECT / JOIN → SQL `ORDER BY` 排序展示。MinIO、向量、实时 LLM 全程不参与。

## 三、跨域职责边界（必须遵守）

| 项 | 负责方 | 约束 |
|----|--------|------|
| 维护 `tal_talent`（level/years_experience 等） | T 域 | 结构变更走迁移，提前与 M 域说明 |
| 新增"综合评分"数值列（或约定落点） | T 域 | 迁移 + 口径说明（算法/量纲/更新时机） |
| 只读 JOIN + list_results 排序键 | M 域 | 不改 T 域表结构、不写 T 域表 |
| `pos_position` 只读岗位清单（供 T 域白名单） | M 域 | 已有 `GET /matching/positions`，T 域只读 |

## 四、排序键数据契约

### 4.1 能力等级 `tal_talent.level`
- 语义：人才能力等级（S/A/B/C 或 初级/中级/高级/骨干/专家…），由 T 域档案 Agent②/测评回写。
- **T 域待办**：收敛取值枚举并写进字段说明。推荐 `S/A/B/C/D` 单字符（字典序=等级序），
  或 `P1~P8` 数字字符串（字典序亦=等级序）。避免"初级/中级/高级"中文（字典序 ≠ 等级序）。
- **M 域排序**：`JOIN tal_talent`，`CASE WHEN level IS NULL OR level='' THEN 1 ELSE 0 END, 等级映射 DESC, match_result.score DESC`。
  等级映射用可移植 CASE（MySQL/SQLite 双库兼容），示例见 §6.1。

### 4.2 从业经验 `tal_talent.years_experience`
- 语义：从业年限整数（年）。T 域简历解析回写，人工可覆盖。
- **T 域待办**：无（字段已存在）。仅需保证解析/人工维护持续有效。
- **M 域排序**：同上 JOIN 分支，`ORDER BY tal_talent.years_experience DESC`（NULL 用 COALESCE 处理或 CASE 垫底）。
  注意与现有 `sort_by=years`（匹配达标分，来自 dimension_json）区分：
  - 建议新增排序键值 `exp_years` = 真实从业年限；
  - 保留 `years` = 匹配时按岗位要求算的达标分（口径：达标度）。

### 4.3 综合评分（新增，依赖 T 域）
- **T 域待办（二选一）**：
  1. 推荐：`tal_talent_report` 新增数值列 `quality_score`（0-100 小数或整数），报告刷新时同步更新；
  2. 兜底：仅保证 report JSON 含可算分项（skills/highlights/shortcomings/potential），M 域按约定公式现算——不推荐（等于把口径散在两处）。
- **口径建议**（需 T 域最终拍板，示例）：`quality_score = level_分×40% + potential_分×30% + 档案完整度×30%`，其中
  `level_分`(S=95/A=85/B=75/C=60)、`potential_分`(P7=95/P6=85/P5=75/空=60)、完整度=简历文本长度/解析字段齐全度折算。
- **M 域排序**：JOIN `tal_talent_report`（一对多注意按最新报告去重，或约定 report 每人才仅一行），
  `ORDER BY quality_score DESC`。新增排序键值 `quality_score`。
  > 提醒：与现有 `sort_by=quality`（M 域匹配时自算的素质维度分）语义不同，键名不要冲突，前端选项文案写明来源。

## 六、M 域侧改动清单（T 域数据就绪后执行）

### 6.1 `app/routers/matching.py` — list_results 增加排序键

在现有 `level` JOIN 分支基础上扩展（`exp_years`/`quality_score`/`level` 共用一个 JOIN 查询）：

```python
from sqlalchemy import select as sa_select
from sqlalchemy import text as sa_text
from app.models.talent import Talent
# 若综合评分落 report 表：from app.models.talent_report import TalentReport
# 并加 .join(TalentReport, ...)（最新报告每人仅一行时可直接 join）

# 等级映射 CASE（MySQL/SQLite 通用），按 T 域最终枚举调整
_LEVEL_MAP = ("CASE WHEN tal_talent.level = 'S' THEN 4 "
              "WHEN tal_talent.level = 'A' THEN 3 "
              "WHEN tal_talent.level = 'B' THEN 2 "
              "WHEN tal_talent.level = 'C' THEN 1 ELSE 0 END")

if sort_key == "level":
    # 字符串等级 → 空值垫底 + 映射序降序 + score 兜底
    order_expr = sa_text(
        "CASE WHEN tal_talent.level IS NULL OR tal_talent.level = '' THEN 1 ELSE 0 END, "
        + _LEVEL_MAP + " DESC, match_result.score DESC, match_result.id DESC")
else:  # exp_years / quality_score：数值列，空值垫底 + 数值降序 + score 兜底
    order_expr = sa_text(
        f"CASE WHEN {sort_key} IS NULL THEN 1 ELSE 0 END, "
        f"{sort_key} DESC, match_result.score DESC, match_result.id DESC")

stmt = (sa_select(MatchResult)
        .join(Talent, MatchResult.talent_id == Talent.id)   # level/exp_years 在 talent 表
        .where(*where)
        .order_by(order_expr)
        .offset((page.page - 1) * page.page_size)
        .limit(page.page_size))
row = [MatchResultOut.model_validate(r) for r in db.scalars(stmt).all()]
```

要点：
- 保留"空值垫底 + score/id 兜底"，保证分页全局序稳定；
- `exp_years` 直接对 `tal_talent.years_experience` 排序；`quality_score` 对 report 列排序；
- schema 说明 `sort_by` 允许值同步到注释与前端选项。

### 6.3 口径与展示
- 列头/选项文案明确数据来源，避免验收时把"M 域快照分"和"T 域研判分"混为一谈；
- 结果行可加 tooltip："能力等级/从业年限来自人才档案（最新研判），匹配分为发起匹配时快照"。

## 七、排序口径提醒（验收前必读）

1. **快照 vs 实时**：`match_result.dimension_json`（skill/degree/years/quality）是**匹配时刻快照**；
   `tal_talent.level` / `years_experience` / `quality_score` 是**当前最新研判**。两者并存、口径不同，
   列表排序允许用最新研判字段（实时 JOIN），但"匹配依据解释"仍读快照，两处不混用。
2. **NULL/脏值**：T 域新列未回填前会大量 NULL → 排序键一律空值垫底（不置顶），
   页面不因空值报错；可在联调前由 T 域批量回填一次。
3. **一对多风险**：若 report 表每人才多行（历史版本），JOIN 会放大行数 → 只 JOIN 最新一条
   （按 updated_at 或约定 report 单行），务必联调核对总数与 `count_rows` 一致。

## 八、验收步骤

1. T 域按 §5 完成字段落地，提供：列名、取值样例、回填 SQL、更新时机说明。
2. M 域执行 §6 改动，`py_compile` + 内存 SQLite 行为验证：
   - 有值人才排在无值人才前；
   - `exp_years` 按 8>5>3>NULL 递减；`level` 按 S>A>B>C>NULL；`quality_score` 递减；
   - 分页翻页全局序稳定（跨页不重复/不跳号）；
   - 与 `count_rows` total 一致（验证 JOIN 未放大行数）。
3. 前端核对：下拉四项来源标注、默认 score、切换后 `page=1` 重新加载。
4. 演示路径：岗位管理 → 发起匹配 → 结果页切换四种排序 → 对比列数据与 tooltip 来源说明。

## 九、风险与回退

- **T 域字段未按期落地**：M 域仅保留 `level`/`exp_years`（现成字段），`quality_score` 选项暂不下发，功能不受阻。
- **枚举口径返工**：level 映射集中在 list_results 一处 CASE，改一处即可，勿在多处散写映射。
- **排序性能**：JOIN + 函数排序无法走索引，当前数据量（百级）无碍；量大时建议把排序字段冗余进
  `match_result` 或在人才表加索引列，另行评估。
- 本指南不引入对 T 域向量/实时 LLM 的依赖，T 域向量体系调整不影响 M 域。
