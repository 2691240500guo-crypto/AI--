## 二、重点工作详情

### 1. 岗位匹配域数据表建设
- 新建 4 张业务表及 ORM 模型（`app/models/matching.py`）：
  - `pos_position` 业务岗位（关联 sys_position / sys_dept，编码唯一）
  - `match_rule` 匹配规则（rule_json 存维度权重）
  - `match_result` 匹配结果（score 0-100，UNIQUE(talent_id, position_id) 保证幂等）
  - `match_push_log` 预警推送日志（type: reserve/vacancy）
- 生成 Alembic 迁移（`513968600ebc`）并执行至云数据库（120.77.177.232:3306/adtp_db），库内共 17 张表
- **设计决策**：match_result.talent_id 只建索引不加外键（人才表属 T 域未建，避免越界）
- 交付改动记录表 `docs/岗位匹配域建表改动记录_2026-08-31.xlsx`（改动概览 + 字段明细两 sheet）

### 2. 后端功能开发（13 个接口全量实现）
分层结构 router → service → dao → model，全部走统一权限 `matching:*`：

| 模块 | 接口 | 说明 |
|---|---|---|
| 岗位管理 M-1 | GET/POST/PUT/DELETE /positions + 详情 | CRUD，编码唯一校验，有匹配结果禁止删除 |
| 画像向量化 M-2 | POST /positions/{id}/vector | 说明书 → bge-m3 embedding → Milvus position_vec |
| 匹配规则 | GET/POST /rules | 权重 JSON 可配置 |
| 双向匹配 M-3 | POST /match | 向量检索 + 硬过滤 + 软加权算分 + 幂等落库 |
| 结果查询 | GET /results、GET /result/{id}/explain | 筛选分页 + LLM 解释 |
| 储备/空缺预警 M-5 | GET /alerts、POST /alerts/generate | 空缺/储备预警，联动消息中心 |
